# 飞书卡片 CLI 方案分析

基于 [[feishu-card-cli|飞书消息卡片与 CLI 发卡方案]] 的结构性分析，提炼可复用的飞书卡片设计方法论，特别是对 E3 AI 工作台飞书端交互的指导价值。

## 卡片设计三层架构

```
上层：自然语言触发（Claude Code Skill）
    ↓
中层：模板 + 变量（JSON 模板 + 最小变量集）
    ↓
底层：飞书 CLI（lark-cli：上传/发卡/跨群）
```

## 变量-锚点分离模式

这是整个方案的精髓：

```
变量（每次换）         锚点（永远不变）
├── 标题                ├── header 颜色
├── 副标题              ├── 按钮文案
├── 封面图              ├── 品牌元素
├── 链接                ├── 卡片布局
├── 日期                └── 设计语言
└── 数据内容
```

**设计原则**：变量管"每次都要换的内容"，锚点管"品牌一致性"。

## 三种实现路径对比

| 路径 | 适用场景 | 优势 | 劣势 |
|------|---------|------|------|
| 搭建工具（cardkit） | 一次性复杂卡片 | 可视化拖拽，新手友好 | 不可复用，AI 接不进去 |
| 飞书 CLI | 日常高频发卡 | 模板复用，批量分发 | 需要 JSON 基础 |
| Claude Code Skill | 高频固定场景 | 自然语言触发，零操作 | 需要封装成本 |

## 卡片迭代方法论

```
说一句话 → Claude 改 JSON → CLI dry-run 真机预览 → 看效果继续说话
```

几个回合定稿一个细节，不需要前端、不需要设计稿、不需要 UI 工具。

## 对 E3 AI 工作台的启示

### 卡片类型映射

| E3 AI 工作台场景 | 卡片类型 | 变量 | 锚点 |
|-----------------|---------|------|------|
| 每日运营概览 | 单向推送 | 订单量/库存预警/到期提醒 | 浅蓝 header + 品牌色 |
| 套餐创建通知 | 单向推送 | 商品名/盒规/套餐列表 | 绿色 header（成功） |
| 捡漏结果 | 交互式 | 各渠道捡漏数量 | [一键捡漏] 按钮 |
| 预售审单 | 交互式 | 批次/订单数/商品 | [一键审核] 按钮 |
| 库存预警 | 单向推送 | SKU/库存/警戒线 | 红色 header（预警） |
| 周报 | 单向推送 | 套餐数/捡漏数/审单数/人天 | 浅蓝 header |

### 飞书端交互设计原则

1. **推送类卡片**：定时/事件触发 → lark-cli 自动发卡
2. **交互类卡片**：按钮回调 → 飞书事件订阅 + 后端处理
3. **预警类卡片**：阈值触发 → 红色 header 突出显示
4. **周报类卡片**：定时汇总 → 数据聚合 + 卡片渲染

### 技术实现路径

```
E3OMS 事件 → AI 引擎处理 → 飞书 CLI 发卡
    │              │              │
    ├── 库存变动     ├── 规则引擎     ├── 推送卡片
    ├── 订单状态     ├── 预测模型     ├── 交互按钮
    ├── 套餐创建     ├── 数据聚合     └── 流式更新
    └── 定时任务     └── 推荐算法
```

## 跨群分发模式

E3 AI 工作台可能需要向不同岗位的飞书群推送差异化内容：

```bash
# 运营群：推送看板 + 捡漏 + 预售方案
# 客服群：推送预售审单
# 商品群：推送套餐创建结果
# 管理群：推送周报
```

通过 chat_id 区分目标群，lark-cli 一行 for 循环搞定。
